# PHONOS — ggml-based Speech + Text Inference Engine

A production-minded, cross-platform inference engine built on top of **ggml**
(MIT). ggml is the tensor/compute backend only; all model logic, audio
front-end, KV-cache management, scheduling and decoding live in `src/`.

Design rules (these prevent the classic bottlenecks):

1. **Three layers, strict separation**
   - Model-logic layer (`src/model/*`, `src/audio/*`) — portable, no device calls.
   - Runtime layer (`src/runtime/*`) — allocator, KV cache, graph planner, backend dispatch.
   - Device backend layer — vendored ggml (CPU now; Metal/CUDA/Vulkan auto-dispatched by ggml's registry when compiled in).
2. **Prefill and decode are separate optimized paths.** Prefill processes chunks
   with large matmuls; decode is a single-token memory-bound path reusing a
   static compute-graph plan and a paged KV cache. No re-computation of history.
3. **Zero allocations in the hot loop.** One `ggml_gallocr` arena sized once,
   reused for every step. Graphs are rebuilt into pre-reserved buffers only.
4. **Quantization is first-class.** Native GGUF types (Q4_0/Q4_1/Q5_K/Q8_0/F16…)
   load straight into ggml contexts; per-tensor type from file, no dequantize-on-load.
5. **Backend selected at runtime**, never hardcoded in model logic. CPU is the
   universal fallback; Apple→Metal, NVIDIA→CUDA, broad-GPU→Vulkan come free via
   ggml's dynamic backend registry (`GGML_BACKEND_DL`), zero code changes here.
6. **Speech front-end runs outside the inference hot path** (log-mel on raw PCM,
   streaming 30 ms frames, encoder caches stable context, no re-processing of
   already-consumed audio).
7. **Single-header public API** (`include/phonos.h`) for embedding/demo use;
   the engine itself stays modular C/C++ — single-header is the *interface*,
   not the implementation.

## Repository layout

```
phonos/
├── PLAN.md                     ← this file
├── CMakeLists.txt              ← top-level build (engine + tools + tests)
├── cmake/                      ← helper modules
├── third_party/ggml/           ← vendored ggml (MIT, pinned commit)
├── include/phonos.h            ← single-header public C API
├── src/
│   ├── core/    log, error codes, ref-counted handles
│   ├── io/      gguf loader (weights+metadata), quantized tensor ingest
│   ├── model/   hparams, transformer blocks (text decoder), vocab/tokenizer
│   ├── runtime/ backend registry init, gallocr arena, KV cache, graph plan,
│   │            prefill/decode paths, sampler (greedy/temp/top-k/top-p)
│   └── audio/   pcm reader, log-mel feature extractor, speech encoder graph
├── tools/       phonos-cli: info / run / generate / transcribe
├── scripts/     make_test_model.py (synthetic GGUF validation model),
│                quantize.py (F32→Q4_0 etc.)
├── tests/       unit + integration (ctest)
└── platform/    android_jni.cpp, macos_bridge.mm, linux_main.cpp, windows_main.cpp
                 (thin adapters — added in Phase 4, stubbed now)
```

## Phases

| Phase | Deliverable | Validation gate |
|---|---|---|
| P0 | Vendor ggml @ pinned commit, CMake superbuild, CPU-only default | `cmake --build` green, `ggml_backend_dev_by_type(CPU)` works |
| P1 | GGUF loader + tiny synthetic text LM (KV cache, prefill/decode, sampler) | Deterministic greedy tokens vs fp32 reference computed in Python |
| P2 | Audio front-end (log-mel) + speech encoder → conditioning vectors feeding the LM (cross-attn-style adapter) | Synthetic "speech" (known tone sequence) maps to known token ids; end-to-end transcribe test passes |
| P3 | Quantization: Q4_0/Q8_0 weights via scripts/quantize.py; perplexity-free golden-output check | Quantized run reproduces F32 outputs within tolerance; peak RSS ≈ model size + cache |
| P4 | Backend dispatch flags (Metal/CUDA/Vulkan ON per host), dynamic-backend loading, platform stubs | `--list-backends`; falls back to CPU cleanly where GPU absent |
| P5 | Benchmarks & docs: tokens/s prefill/decode, RTF for audio, memory report | README + benchmark table committed |

## Model note
The target "Phonon-2"-class model (~164 MB quantized) is small enough that the
whole engine must run comfortably on a phone. Until we can pull the real
weights, **validation uses a synthetic GGUF model generated by
`scripts/make_test_model.py`** with the exact same architecture features
(embedding, N transformer layers, RoPE, KV cache, audio-conditioning tensors),
so every engine path is exercised identically. Swapping in real weights later
is a config change, not a code change.
